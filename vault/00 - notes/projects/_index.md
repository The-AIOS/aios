# Projects Map of Content

> One `.md` file per active project. This index is the team's living registry of what we're building.

---

## Convention

Each project gets its own note in this folder. The index below is maintained as projects are added or archived — every new project should be listed here with its current status.

### Standard project note structure

Every project note should include:

**Frontmatter:**
```yaml
---
tags:
  - project
  - project/<status>   # active, idea, or archived
status: active          # active | idea | archived
path: ~/code/<repo>     # filesystem path to the project
stack:
  - TypeScript
  - Next.js
created: 'YYYY-MM-DD'
updated: 'YYYY-MM-DD'
---
```

**Sections:**
1. **Overview** — what it is and who it serves
2. **Tech Stack** — frameworks, languages, tools
3. **Architecture** — folder structure and key patterns
4. **Current State** — branch, deployment, last activity
5. **To-Dos** — three tiers: High Priority / Normal / Ideas
6. **Decisions Log** — important choices with rationale
7. **Session Notes** — running log of work sessions
8. **Links** — cross-references to related notes

### Status values

| Status | Meaning |
|--------|---------|
| `active` | Currently being developed or maintained |
| `idea` | Concept stage — not yet started |
| `archived` | No longer active; kept for reference |
