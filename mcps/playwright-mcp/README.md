# Playwright MCP

Browser automation for the AI-OS. Auto-publish content, test web apps, capture screenshots, interact with any website programmatically.

## What it does

- Navigate to any URL, click elements, fill forms, submit
- Take screenshots and PDFs of web pages
- Auto-publish to Substack, LinkedIn, X/Twitter (auth once, agent publishes headlessly forever)
- Test web applications (verify UI behavior, debug rendering)
- Scrape content with full JS rendering

## Not a connector — there is nothing to register

This folder lives under `mcps/` by history, but **it contains no MCP server**: no server code, no
`FastMCP`, no stdio transport. Verified 2026-08-27 while auditing all bundled folders for the connector
manifest.

It is a Python toolkit, invoked directly — `.venv/bin/python cookie_import.py`, and Playwright itself
driven from agent code. `connector.json` here carries `registers: false`, so the AIOS App neither lists
it as a connector nor reads its missing registration as drift.

An earlier audit recorded this folder as *"bundled but registered nowhere, no register command in the
README"* and proposed authoring one. There is no server to point such a command at; writing one would
produce a registration that fails at first use. The honest fix is this section.

## Example usage

Ask Claude naturally — it drives the browser with your saved auth:

```
"Publish the next post to Substack using my saved auth — title and body from this markdown file"
"Cross-post it to LinkedIn and X"
"Take mobile + desktop screenshots of this URL and save them to 02 - assets/"
"Scrape the latest 5 titles from my LinkedIn feed and summarize the themes"
"Check analytics on my last tweet and return the engagement numbers"
"Verify this URL loads clean, no console errors, screenshot if anything breaks"
"Log into this admin panel and pull the last 7 days of signups as a CSV"
```

Authentication comes from Chrome cookies (see below) — no passwords, no magic links, no re-logins.

## Install

```bash
bash mcps/setup.sh    # installs playwright + chromium + browser-cookie3 in .venv
```

Or manually:

```bash
cd mcps/playwright-mcp
python3 -m venv .venv
source .venv/bin/activate
pip install playwright browser-cookie3
playwright install chromium
```

## Authentication — cookie import from Chrome

Playwright uses **browser storage state** to authenticate. We extract cookies from your already-logged-in Chrome (same pattern as `slack-mcp` — single consistent approach across the vault).

### One command, all sites

Make sure you're signed in to Substack, LinkedIn, and X/Twitter in **Chrome** (web, not desktop apps). Then:

```bash
~/aios/mcps/playwright-mcp/.venv/bin/python ~/aios/mcps/playwright-mcp/cookie_import.py
```

This reads cookies for all supported sites, validates the critical session cookie is present, and writes Playwright storage_state JSON files to `auth/<site>.json`.

**Import a subset:**

```bash
python cookie_import.py substack         # just one
python cookie_import.py substack x       # multiple
```

**Supported sites:** `substack`, `linkedin`, `x` (configured at the top of `cookie_import.py`).

### macOS Keychain prompt

First run, macOS will ask for your login password — browser-cookie3 reads Chrome's encrypted cookie store via Keychain. Click **"Always Allow"** to skip future prompts.

### Auth files

```
auth/
├── substack.json    ← generated by cookie_import.py
├── linkedin.json    ← generated by cookie_import.py
└── x.json           ← generated by cookie_import.py
```

All gitignored — each user authenticates on their own machine.

### Token refresh

If you change your password or the site rotates sessions, the cookies expire. Just re-run `cookie_import.py` — it re-reads Chrome's current state.

### Adding a new site

1. Sign in to the site in Chrome
2. Edit `cookie_import.py` → add to the `SITES` dict: `"mysite": (["mysite.com"], "session_cookie_name")`
3. Run `python cookie_import.py mysite`

## Using saved auth in a script

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    ctx = browser.new_context(storage_state="mcps/playwright-mcp/auth/substack.json")
    page = ctx.new_page()
    page.goto("https://substack.com/publish")
    # you're logged in — publish content headlessly
```

## Site-specific notes

### X / Twitter — needs stealth for interactive use

Cookie import works for loading pages and reading timeline data. For **posting tweets or heavy interaction**, Twitter's bot detection blocks Playwright even with valid cookies. Install `playwright-stealth` when you need that:

```bash
pip install playwright-stealth
```

```python
from playwright_stealth import stealth_sync
# ... after page = ctx.new_page():
stealth_sync(page)
page.goto("https://x.com/compose/post")
```

Add this when X auto-posting becomes a priority — today, cookie import alone is enough to prove the auth works.
